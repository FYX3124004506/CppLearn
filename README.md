# CppLearn

CppLearn 是一个面向长期学习和复习的 C/C++ 示例代码仓库。仓库中的代码以小型、独立、可验证为主要特点，配套记录基本概念、语法规则、编译过程、常见错误和实践方法。

当前内容以 C 语言基础为主，后续可以在保持现有目录和命名规则稳定的前提下，逐步增加 C 语言进阶内容、C++ 基础、数据结构、算法和小型练习项目。

## 项目定位

本仓库主要用于：

- 保存学习过程中可以重复编译和运行的最小示例；
- 将一个知识点拆分为一个容易阅读、容易验证的源文件；
- 记录语法、编译器行为、输入输出和常见错误；
- 为配套学习笔记提供可执行的代码参考；
- 为后续增加练习题、实验代码和小型项目保留清晰的扩展空间。

仓库中的示例优先服务于学习和复习，不以构建完整应用为目标。需要多个源文件协作的内容，可以在后续单独建立项目目录，避免破坏已有的单文件示例。

## 目录结构

当前目录大致如下：

```text
CppLearn/
├── c/
│   └── C语言常见概念/
│       ├── 01_hello_world.c
│       ├── ...
│       ├── 10_comments.c
│       ├── README.md
│       ├── c.sln
│       ├── c.vcxproj
│       └── c.vcxproj.filters
├── .gitignore
└── README.md
```

后续扩展时，建议按以下原则组织：

- 单个知识点可以使用一个独立源文件；
- 多个源文件共同组成的内容应放入单独项目目录；
- 每个主题目录都应包含自己的 README；
- 构建配置应尽量放在对应主题目录内；
- 编译产物、IDE 缓存和临时文件不得作为学习源码提交。

## 学习路线

推荐按照由浅入深的顺序学习和扩展：

1. 程序结构、`main` 函数和基本输出；
2. 字符、字符串、转义字符和格式化输入输出；
3. 变量、数据类型、常量和运算符；
4. 语句、分支、循环和跳转；
5. 数组、指针、字符串处理和函数；
6. 结构体、枚举、联合体和类型定义；
7. 预处理、文件操作、动态内存和错误处理；
8. 多文件编译、项目组织和小型综合练习；
9. 在 C 语言基础稳定后，再扩展到 C++ 语法和标准库。

当前仓库只完成了其中一部分基础示例，学习路线用于指导后续内容扩充，不要求一次性实现全部主题。

## 使用方式

### 使用 GCC 或 MinGW

进入具体示例目录后，选择一个源文件单独编译：

```bash
gcc -std=c11 -Wall -Wextra -Wpedantic 01_hello_world.c -o 01_hello_world.exe
```

Windows PowerShell 中运行：

```powershell
.\01_hello_world.exe
```

每个入门示例通常包含自己的 `main` 函数，因此不能把同一主题目录下的所有源文件一次性链接。具体命令、输入数据和注意事项以对应目录的 README 为准。

### 使用 Visual Studio

如果主题目录提供 `.sln` 或 `.vcxproj` 文件，可以使用 Visual Studio 打开对应工程。多个示例各自包含 `main` 函数时，应通过工程配置选择当前要构建的源文件，不能让多个示例同时参与链接。

### 阅读代码的建议顺序

1. 先阅读示例文件顶部的说明和学习目标；
2. 再阅读 `main` 函数中的最小可运行代码；
3. 对照注释观察输入、处理和输出之间的关系；
4. 自行修改一个变量、分支或输入值后重新编译；
5. 阅读对应主题 README 中的扩展和易错点。

## 代码约定

- C 语言示例默认使用 C11 标准；
- 示例文件名使用连续编号加英文主题名，例如 `08_input_and_output.c`；
- 文件名只表达一个主要学习主题，避免在一个文件中堆叠无关内容；
- 每个可独立运行的示例保留一个 `main` 函数；
- 注释说明概念、原因、边界和易错点，不重复翻译每一行代码；
- 输入示例应尽量限制缓冲区长度，并检查输入函数的返回值；
- 编译时启用常见警告，发现警告后应先判断原因再提交；
- 复杂示例可以拆分为多个源文件，但应在目录 README 中说明编译顺序。

## 新增内容的建议流程

增加新的学习内容时，可以按以下步骤执行：

1. 确认它属于现有主题，还是需要建立新的主题目录；
2. 为单文件示例选择下一个连续编号和清晰的英文文件名；
3. 在源文件中补充学习目标、必要注释和可观察的输出；
4. 更新对应主题 README 的目录表和学习路线；
5. 使用 GCC 或现有构建系统进行编译，并开启警告选项；
6. 运行程序，验证正常输入、边界输入和预期错误提示；
7. 检查没有提交可执行文件、目标文件、IDE 缓存或敏感信息；
8. 使用简洁的 Git 提交信息记录本次主题变化。

如果新增内容依赖前置知识，应在 README 中标明推荐学习顺序，而不是只增加文件名。

## 验证与维护

提交代码前至少检查以下内容：

- 源文件可以使用项目规定的标准编译；
- 编译过程中没有未解释的警告；
- 程序可以运行，输出与代码逻辑一致；
- README 中的文件名和链接真实存在；
- 工程文件没有把多个 `main` 同时加入同一个链接目标；
- Git diff 只包含本次学习内容；
- 没有密码、Token、私钥或其他敏感配置；
- 没有把构建产物和本地开发环境文件加入版本库。
