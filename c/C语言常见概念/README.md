# C 语言常见概念：示例代码

本目录用于保存 C 语言入门阶段的独立示例，覆盖基础概念、语句结构、输入输出和注释说明。每个 `.c` 文件聚焦一个主要知识点，并包含自己的 `main` 函数，适合单独编译、运行和修改。

本目录当前包含程序结构、字符与字符串、输入输出、控制结构、注释及类型与变量等基础示例。后续可按主题继续扩展；新增内容应保持编号、命名和文档结构连续，不要求把所有知识点集中到一个文件中。

当前示例覆盖以下基础内容：

## 推荐学习方式

建议每次只学习一个示例：

1. 先阅读文件顶部的说明，明确本文件要观察的知识点；
2. 不修改代码运行一次，记录程序输出；
3. 对变量、格式说明符或输入值做一个小修改；
4. 重新编译，观察输出变化或编译器提示；
5. 对照注释解释变化原因；
6. 学完后再阅读下一个编号的示例。

对于 `07_keywords_bad.c`，错误写法被放在注释中，是为了展示错误原因，不能把注释符号删除后直接当作正常程序编译。对于 `08_input_and_output.c`，应特别关注输入函数的返回值、字段宽度和格式说明符类型。

## 使用 GCC 或 MinGW

在本目录中选择一个源文件单独编译。推荐开启 C11 标准和常见警告：

```bash
gcc -std=c11 -Wall -Wextra -Wpedantic 11_data_types_and_variables.c -o 11_data_types_and_variables.exe
```

Windows PowerShell 中运行：

```powershell
.\11_data_types_and_variables.exe
```

也可以将输出文件放入临时构建目录，避免把可执行文件留在源代码目录中。无论输出位置在哪里，都不应把 `.exe`、`.o`、`.obj` 等构建产物提交到 Git。

### 输入示例

`08_input_and_output.c` 需要输入姓名、年龄和身高。PowerShell 可以使用受控输入：

```powershell
@("小明", "20", "1.75") | .\08_input_and_output.exe
```

手动运行时，也可以依次输入：

```text
小明
20
1.75
```

测试时应额外尝试空输入、过长文本、非数字年龄和非数字身高，观察程序是否按照代码中的检查逻辑处理输入失败。

## 使用 Visual Studio

本目录提供 `c.sln`、`c.vcxproj` 和 `c.vcxproj.filters`。工程中登记了 01–11 号源文件，但每个示例都有独立的 `main` 函数，因此默认只构建一个示例，其他示例设置为不参与当前构建。

切换示例时，可以采用以下方式：

1. 在解决方案资源管理器中确认要运行的源文件；
2. 调整工程文件中对应配置的 `ExcludedFromBuild`；
3. 确认其他包含 `main` 的源文件不参与同一次链接；
4. 重新生成并运行项目。

如果只需要快速验证单个文件，使用 GCC 通常更直接。Visual Studio 工程主要用于查看文件组织和进行 IDE 调试。

## 编译流程

```text
.c 源文件
    ↓ 预处理：处理 #include、#define，并移除注释
    ↓ 编译：翻译为汇编代码
    ↓ 汇编：生成目标文件
    ↓ 链接：与库函数链接，生成可执行文件
```

注释通常在预处理阶段被移除，不会直接成为程序运行时的指令；但清晰的注释可以帮助学习者理解编译前后的源代码意图。

## 新增示例的规则

向本目录增加文件时，建议遵循以下约定：

- 文件名使用“连续编号_英文主题名”的形式，例如 `11_variables_and_types.c`；
- 一个文件只讲一个主要概念，相关概念可以作为辅助说明；
- 保留一个可独立运行的 `main` 函数；
- 文件顶部说明学习目标、关键结论和必要的安全注意事项；
- 注释解释为什么这样写、容易错在哪里，不逐行重复代码；
- 对输入使用合适的长度限制，并检查输入函数返回值；
- 在本 README 的示例表中增加对应行；
- 如果加入 Visual Studio 工程，需要同步更新 `.vcxproj` 和 `.filters`；
- 编译、运行并检查警告后再提交。
